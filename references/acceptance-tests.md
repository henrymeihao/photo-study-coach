# 摄影拆解验收用例

以下是对 Skill 输出的验收规则，不是声称已运行视觉模型测试。

## T1：单窗人像，明暗清晰
输入：有可见面部侧向亮暗、窗户未必在画面内的人像。
期望：指出画面哪侧的脸、鼻影/下巴影和过渡；区别光向与软硬；提出窗口为假设而非事实；可用人物转向和窗距变化验证；交代背景亮度、肤色与冷暖关系。
失败：只写“柔和侧光、高级电影感、建议柔光箱”；编造 45° 柔光箱或 1:4 光比。

## T2：阴天户外人像
输入：投影不清、光源广泛且面部均匀的人像。
期望：解释证据不足以确定精确光向；分析明度分离与背景竞争；可能推荐负补光或调整背景；允许无灯示意。
失败：根据成片捏造主光/轮廓光/背景灯三点布光。

## T3：城市夜景与混合光
输入：画面有暖色招牌、偏冷环境与人的肤色。
期望：分别描述色光来源、白平衡与后期均可能形成观感；检查肤色染色和高光边缘；说明色相、明度、饱和度空间位置以及拍摄时优先选择位置。
失败：直接断言使用某 Lightroom 预设或固定色温。

## T4：草原/湖泊/雾气风光
输入：有层叠山脉、雾和人物的风光照。
期望：分析前中后景、空气透视、明度层级、主体占比、等待天气时机；把「长焦压缩」与拍摄距离效应区别开。
失败：只有“三分构图、冷色调、情绪感”，或给出未经证实的镜头型号。

## T5：无法获取参考图
输入：只有网页标题或文本，无图片像素或视觉可见内容。
期望：保留标题与来源，只给文案级信息；明确不能做具体光线、配色或场景推理，请用户提供图片。
失败：从作品标题生成虚构的照片分析。

## T6：数值和可视化
输入：截图含网页 UI、边框或文字。
期望：只统计实际照片区域，写明采样/算法；没有像素就不输出占比、色卡/直方图，示意中的推测光源用虚线。
失败：展示未经计算的百分比、错误对齐标注或凭空确定光强 EV。

## T7：学习价值与可迁移性
输入：同一作者 3–6 张图片。
期望：综合规律至少用两张图的具体观察佐证；每张重点图有复拍起点和可验证条件；明确观察结果与作者意图的区别。
失败：将单图效果概括为整个作者的固定风格。

## T8：单点主技巧优先级（新）
输入：低机位水洼倒影占据画面大面积，同时可见冷暖配色和建筑引导线。
期望：首屏只强调一项最值得学的决定性技法（例如低机位利用倒影），指出具体位置证据、为何关键、为什么比其它候选更值得先学；其它色彩/构图深读仍可展开。
失败：在首屏并排罗列“三分构图、低机位、冷暖色调、电影感、对称”且不做取舍；只写“学会低机位”没有可见证据。

## T9：有依据的反事实与得失（新）
输入：与 T8 相同的可见照片。
期望：提出一个单变量方案（如保持位置与拍摄意图尽量一致、只提高机位），说出画面下部倒影占比或关注路径**可能**如何变、环境交代可能增加但倒影冲击力减弱、两张照片如何现场比较；标记为预测。
失败：同时改机位、焦距、时间和构图，却说“只改一件事”；只写“会不好看”；把虚构的对比效果当成已经验证；没给验证标准。

## T10：拍摄意图与限制（新）
输入：纪实街拍、背景有多个行人的照片，用户意图是表现人群密度；或不可复现的偶发瞬间。
期望：不把拥挤自动判为干扰；按表达目标选择主技巧并判断反事实的收益与代价。对无法严格控制的瞬间采用概念推演或近似情境复拍，说明限制。
失败：强迫“去掉行人/背景虚化”，忽略用户意图；宣称可以精确复现独一无二的时间和天气条件。

## T11：未指定格式的照片拆解
输入：一张可读取的本地照片，用户说“用 photo-study-coach 拆解这张照片”，没有指定输出格式。
期望：在聊天里按 card-format.md 模板输出学习卡，栏目和顺序与模板一致，已按“交付前逐条检查”表处理参数和标签。照片级分析满足 T8、T9。用户要文件时再存 Markdown 或做 HTML。
失败：栏目顺序或名称与模板不同；缺回传说明；不能写文件却声称生成了文件；未打开就声称 HTML 已验证。

## T12：用户明确只要文字
输入：可见照片，用户说“只在聊天里简短点评，不要生成文件”。
期望：仅给文字，保留主技巧与适量依据，遵循用户要求不生成 HTML 或 Markdown。
失败：忽略用户格式要求，仍机械制作手册。

## T13：三分钟卡与现场决策
输入：一张地标旅行人像，用户未指定全面报告。
期望：默认展开短卡，学习者无需开附录即可找到观察条件、决定、调整变量、可见检查标准；EXIF和深度分析折叠，窄屏可读。
失败：只是给旧长报告加一段摘要，全部技术分析仍默认铺开；现场指导只写“注意构图”。

## T14：迁移与边界
输入：同T13。
期望：1–2个新场景说明同一视觉机制、具体动作、适用和不适用条件；需要时提供单变量教学示意，原图保留。
失败：堆几张相似图片当作迁移；把示意当成真实重拍，固定所有照片都用人物距离变量。

## T15：A/B回流与混杂
输入：用户回传A/B，B还改变了焦距或受光。
期望：实际读图，说明已做到什么、定位最大差异、指出混杂而不硬判因果、给下一轮唯一动作；只有满足具体标准才记录限定目标的验证结果。
失败：没读图就套反馈；所有问题都建议后期；读过或拍过就称掌握；离线网页展示不能工作的上传/AI分析按钮。

## T16：记录授权与缺图
输入：只有参考照片，没有实拍或既有学习记录。
期望：提供练习与回传说明，不编造实践反馈或掌握状态，不自动创建个人知识库。只收到一张实拍时承认不能成对比较并先给已有证据反馈。
失败：自动保存到未指定知识库；宣称已形成学习闭环或已验证掌握。

## T17：模型看不到图片
输入：当前模型不支持图片输入，或客户端、网关没有把图片真正传给模型，只留下文件名、链接或尺寸。
期望：第 0 步就停下，说明看不到图片，请用户换支持图片的模型或直接上传；只复述来源文字。能看到图时，卡片第一行“我看到的画面”与照片一致。
失败：根据文件名、标题、目录里的其他文件或像素采样数值猜测画面；“我看到的画面”描述了一张不存在的照片却继续分析。

## T18：点评用户自己的照片
输入：用户发来自己拍的一张照片，说“帮我看看哪里能更好”，没说拍摄意图。
期望：先写“这张似乎想突出……”，最多追问一项会改变建议的信息；主技巧是下次只改的一处决定，并给 A/B 练习；指出已经做得好的地方。
失败：罗列五六个问题；把人多、暗、虚化不足自动当成错误；只建议后期修图。

## T19：横移对照里的消失点
输入：正对直路、走廊或轨道拍摄的一点透视照片，对照选择“只横移站位”。
期望：预期变化写明消失点位置基本不变，变化来自近处一侧物体变大、中线从画面一角斜着进入。
失败：写“横移后消失点偏到画面一侧”。

## T25：固定模板与视觉一致性
输入：一张可读取的参考人像照片，用户未指定纯文字。
期望：HTML 从 `references/html-template.html` 填充；页面保留固定的编辑式视觉语言、布局、字体、颜色、组件和交互。内容变化不导致整体视觉风格漂移。
失败：Agent 从空白 HTML 自由设计；引入另一套 CSS 框架、CDN、外部字体或图片；模板结构被随意重写；只在文字里声称“使用模板”但产物没有对应结构。

## T26：模板占位符与内容 Schema
输入：一张有完整原图字节和尺寸的照片。
期望：所有模板占位符均被替换；文字已转义；分析卡、复刻卡和折叠区使用 Schema 规定的结构；无内容的可选模块整体移除；HTML 与 Markdown 的核心结论一致。
失败：残留 `{{...}}`；用户文字被当成 HTML/脚本执行；空标题/空卡片；同一结论在多个模块重复堆叠；HTML 和 Markdown 出现互相矛盾的事实。

## T27：原图坐标与标注层
输入：一张已知原始宽高的照片，标注 3 个可见区域。
期望：SVG `viewBox` 与原图像素宽高一致；叠加层随原图等比例缩放；编号与图例一一对应；标注按钮只在存在标注层时出现；推测使用明确的虚线或文字标记。
失败：坐标按屏幕尺寸硬编码；图片被裁切而标注未同步；编号重复/缺失；无标注却保留按钮；用通用方框冒充准确位置。

## T28：内容密度与响应式呈现
输入：一张包含光影、前景、色彩和人物动作的复杂人像。
期望：首屏一个核心决定；可见速学主体约 300–500 个中文字，通常用 2–4 个分析卡；三要素复刻有具体动作和检查信号；深度内容折叠。桌面端图片与分析并列，约 390px 窄屏上下排列且无横向溢出。
失败：首屏罗列多个并列技巧；正文变成长报告；重复解释同一机制；手机端文字/图片过窄、裁切或横向滚动；所有深度内容默认展开。

## T29：离线、可访问与真实交互
输入：一张内嵌原图的最终 HTML。
期望：无外部网络请求；图片有准确 alt；标注切换可用且有 aria 状态；原生 details 可键盘操作；打印时控件隐藏、折叠内容展开且不明显截断。
失败：引用 CDN/远程图片/在线字体；按钮没有实际行为；缺少可访问名称；打印时重要内容丢失；把静态检查冒充浏览器测试。

## T30：SVG 标注切换状态
输入：包含默认隐藏 SVG 标注层、标注按钮和图例的最终 HTML。
期望：首次打开时 SVG 与图例都隐藏，按钮 \`aria-pressed=\"false\"\`；点击一次后，SVG 的 \`hidden\` 属性被移除、图例显示、按钮变为 \`true\`；再次点击后三者恢复初始状态。必须在真实浏览器中执行两次点击并检查 SVG 实际可见性，不能只检查按钮文本或图例状态。
失败：仅更新 \`aria-pressed\` 或图例，SVG 仍保留 \`hidden\`；对 SVGElement 使用不反映 HTML 属性的 \`.hidden\` expando；点击后按钮状态与标注层/图例不一致。

## 验收方式

逐项审查与本次目标有关的 T1–T19；技术维度只在相关时检验深度，不为得分强制输出全维度长报告。可见照片必须满足主技巧、单变量反事实、现场决策、迁移与回传说明；明确只要分析/文字时遵从例外。T5、T6、T17 的禁止编造始终适用。

至少用一张实际可见照片检查最终产物，实际打开最终HTML验证交互与宽窄布局。格式验证、人工审查、独立会话行为验证、用户实拍效果是不同证据，不互相冒充。没有A/B实拍时，复盘流程仍待实拍验收。


## T20：视觉优先 HTML 学习卡
输入：一张可见的人像或风光参考作品，用户未指定纯文字。
期望：默认交付离线 HTML 与 Markdown；HTML 首屏展示原图、一个核心判断；原图/标注可切换且标注位置准确；深度内容默认折叠；桌面与窄屏布局可读。
失败：大段 Markdown 是唯一默认产物；标注只是通用占位；AI 重绘图冒充原图分析；未实际打开却声称验证通过。

## T21：为什么好看与多维度协同
输入：一张同时包含局部光、前景遮挡、色彩呼应和人物手势的人像。
期望：解释光影、构图、色彩、人物表现如何起作用，指出核心与辅助因素；结论包含画面位置、视觉机制和观看效果。
失败：只描述画面物体；堆砌摄影标签；把各维度写成互不相关的长段落。

## T22：三要素复刻
输入：一张有明确光影、空间关系和色彩组织的参考作品。
期望：给出光线、构图、色彩的现场寻找条件、安排方法和检查信号；步骤可执行并按题材调整。
失败：只给审美形容词；复刻等同于购买相同镜头；没有现场检查标准。

## T23：参数推测与 EXIF 可信度
输入：无 EXIF 的 JPEG 人像，具有明显虚化和局部光影。
期望：先描述视角、透视、距离和景深观感；准确焦段、光圈、ISO、快门和器材型号可标“无法确定”；范围推测须给依据、置信度和替代解释。
失败：编造 85mm、f/1.4、ISO 100、1/500s 等参数；把虚化唯一归因于大光圈；把长焦作为透视压缩的唯一解释。

## T24：不强制 A/B
输入：用户要求分析一张参考照片，没有要求练习或对照。
期望：给自然复刻任务或一个优先动作；只有对照确实能解释某个决定时才可选用 A/B。
失败：机械输出 A/B、固定变量和回传任务，即使与核心学习目标无关。
