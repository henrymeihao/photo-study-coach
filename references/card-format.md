# 学习卡格式

所有交付都用同一张卡。聊天回答、Markdown 文件、按需制作的 HTML 都按这个顺序和标题输出，不增删栏目。

## 模板

```markdown
## P1 · 作者 · 来源链接 · 读取日期

**我看到的画面：**三样具体的东西和它们的位置（只来自直接看图）
**这张最值得学：**一个拍摄决定（证据等级）
**拍摄意图：**用户说的意图；没说就写“这张似乎想突出……（个人解读）”
**画面证据：**具体位置 → 产生的效果
**为什么有效：**一两句机制

**现场四步**
1. 先观察：现场先找什么视觉条件
2. 再决定：按表达目标决定什么
3. 然后调整：只动哪一个变量、怎么动
4. 最后检查：看什么信号

**只改一处会怎样**（预测，未经实拍）
- 固定：……
- 只改：一个变量
- 预期变化：哪个区域怎样变
- 得到：……
- 失去：……

**A/B 练习**
- 准备：场地和条件；需要建议值时写“起点建议：……”
- A：……
- B：和 A 只差“只改”那一处
- 检查：1–2 条肉眼能看出的标准

**换个场景**（1–2 条）
- 场景：做法。适用于……；不适用于……

**拍完回传：**在聊天里发 A、B 两张照片，注明哪张是 A、只改了什么、想突出什么、现场还有什么变化。我会按这张卡的检查标准对比，并给下一轮一个动作。

<details><summary>深度拆解与来源</summary>

- 为什么选这个技巧：2–3 个候选和没选它们的原因
- 与主技巧有关的构图、用光、色彩、镜头分析（每条标证据等级）
- 无法判断的地方
- 已知信息：作者原文或真实 EXIF，注明来源；没有就写“没有作者原文或 EXIF 证实的拍摄参数”

</details>
```

一组照片时，在第一张卡前加“这组照片的共同做法”，每条规律注明它出现在哪几张图（至少两张）。

## 写法要求

- 从“这张最值得学”到“换个场景”不超过 600 字，每项一句话。超出时先删修饰语，再合并重复的证据。
- 标题和栏目名照抄模板，不加粗体以外的格式，不把标题改成链接。
- 证据等级只用：已证实（A）、高可信解释（B）、推测（C）。D 级不能做主技巧。
- 位置用“画面左下”“画面中央偏右”等描述；人物方向写“人物的左手”，不和画面左右混用。
- “拍完回传”一句照抄模板，不改写。

## 交付前逐条检查

把卡里每一句过一遍，出现下列内容时按右栏处理：

| 出现了 | 处理 |
| --- | --- |
| 焦段（mm）、光圈（f/）、快门（1/…）、ISO、色温（K）、EV、光比 | 有作者原文或真实 EXIF 就移到“已知信息”并注明来源；是练习建议就写成“起点建议”；否则删掉 |
| 相机或镜头品牌、灯具型号、修图预设或滑块数值 | 同上 |
| 百分比、色卡、直方图 | 只有你实际计算过像素才保留，并写明统计区域和方法；否则改成定性描述 |
| 主技巧里有“三分”“黄金分割”“电影感”“高级感”“氛围感”“冷暖对比” | 改写成一个拍摄决定 |
| “只改”里有“并且”“同时”“以及” | 拆成一个变量，其余放进“固定” |
| 没写不适用情况的“换个场景” | 补上 |
| 去掉照片仍成立的句子 | 补具体位置和机制 |

## 示例

以下是虚构照片的格式示例，只用于对齐写法，不要把其中结论用到任何真实照片上。

```markdown
## P1 · 示例作者 · https://example.com/work · 2026-11-18

**我看到的画面：**雨后的街道，画面下半部是一大片水洼，水里倒映着画面上方的路灯和一个撑伞的行人
**这张最值得学：**把相机放低到贴近水洼，让倒影占画面下半部（高可信解释）
**拍摄意图：**这张似乎想突出路灯和行人在水洼里的倒影（个人解读）
**画面证据：**画面下方大约一半是水洼，路灯和行人的倒影完整出现在水面，水洼边缘几乎贴着画面底边 → 第一眼先落在倒影里的行人
**为什么有效：**低机位让水面在画面里显得很大，倒影和实景上下呼应

**现场四步**
1. 先观察：雨后找一块平静、比周围暗的水洼，看水里能映出哪个亮的东西
2. 再决定：想让倒影做主角，就让水面占画面下半部
3. 然后调整：相机从胸口高度慢慢降到贴近水面，边降边看倒影面积
4. 最后检查：倒影是否完整，水洼边缘有没有切到主体

**只改一处会怎样**（预测，未经实拍）
- 固定：站位、朝向和视角
- 只改：相机从贴近水面升到胸口高度
- 预期变化：画面下部的水洼可能明显变小，倒影只剩一条，地面和远处街道露出更多
- 得到：街道环境交代更清楚
- 失去：上下呼应的镜像结构变弱，第一眼可能不再落在倒影上

**A/B 练习**
- 准备：下雨后找一块水洼，打开网格线；起点建议：手机主摄或约 35mm 等效视角
- A：相机贴近水面，倒影占画面下半部
- B：位置和视角不变，相机升到胸口高度
- 检查：A 的倒影占画面下部大部分且主体完整；两张只有相机高度不同

**换个场景**
- 湖边或玻璃幕墙：同样降低相机，让反射面变大。适用于反射面平静、反射的东西比周围亮；不适用于水面有风浪或玻璃很脏。
- 室内光滑地板：手机倒过来贴近地面拍人物倒影。适用于地板反光且人物背后有亮光；不适用于地毯或哑光地面。

**拍完回传：**在聊天里发 A、B 两张照片，注明哪张是 A、只改了什么、想突出什么、现场还有什么变化。我会按这张卡的检查标准对比，并给下一轮一个动作。

<details><summary>深度拆解与来源</summary>

- 为什么选这个技巧：低机位放大倒影（选它，去掉后照片失去重点）；等行人走到路灯下（没选，它依赖低机位才出现在倒影里）；暖色路灯配冷色天空（没选，转成黑白后倒影结构仍成立，颜色只是辅助）
- 用光（推测）：画内路灯是最亮的光源，湿地面把它拉成竖向亮条；画外是否还有店铺灯光无法确认
- 无法判断：实际焦段和相机离地高度
- 已知信息：没有作者原文或 EXIF 证实的拍摄参数

</details>
```

## 需要 HTML 时

只在用户要求 HTML 时制作，内容和顺序与上面的卡完全一致：

- 单个文件，图片内嵌，不引用任何外部网址。
- 桌面端照片在左、卡片在右；手机端上下排列，照片保持原比例。
- 标注用叠在照片上的 SVG，坐标按图片宽高的比例计算；推测的标注用虚线；同时保留一张无标注的原图。
- “深度拆解与来源”用 `<details>` 默认折叠。
- 不放上传按钮、AI 点评按钮或保存按钮。
- 能打开浏览器时检查图片、标注位置和窄屏布局；不能打开就在回复里说明没有检查。
